OpenRV64 SoC blocking memory-bus contract
=========================================

Scope
-----

The SoC bus has one requester and one completed transaction at a time. It is a
small blocking interface, not AXI, TileLink, or Wishbone. It has no bursts,
transaction IDs, reordering, retry response, or separate instruction/data
channels.

The core owns the upstream requester port. openrv64_soc_bus_decode translates
physical addresses to target-local byte offsets and selects ROM, memory, or one
MMIO target. All physical base addresses and window sizes are defined only in
rtl/soc/bus/mem_map.v.

Upstream requester interface
----------------------------

    mem_valid       requester -> bus     request is present
    mem_ready       bus -> requester     request completes this cycle
    mem_write       requester -> bus     1 for write, 0 for read
    mem_addr[63:0]  requester -> bus     physical byte address
    mem_wdata[63:0] requester -> bus     write data in byte lanes
    mem_wstrb[7:0]  requester -> bus     one write enable per byte lane
    mem_rdata[63:0] bus -> requester     aligned 64-bit read data
    mem_error       bus -> requester     completion is an access failure

A transaction completes when mem_valid and mem_ready are both high. The
requester must hold mem_write, mem_addr, mem_wdata, and mem_wstrb stable from
the assertion of mem_valid through completion. After completion it must drop
mem_valid or begin the next transaction on the following cycle.

mem_rdata and mem_error are meaningful only on a completed transaction. For a
successful read, mem_error is zero and mem_rdata contains the selected target
word. Write response data is zero and ignored. For a failed transaction,
mem_error is one and mem_rdata is zero.

Address and byte-lane rules
---------------------------

Addresses identify bytes. A target returns the 64-bit word containing the
requested byte, selected by mem_addr[63:3]. mem_addr[2:0] is preserved so MMIO
targets can distinguish registers sharing a 64-bit word.

For writes, mem_wstrb[N] controls mem_wdata[8*N +: 8]. Disabled lanes retain
their previous value in RAM and must not alter writable MMIO state. The bus
does not carry an explicit access-size field; the requester expresses the
write size and lane placement through mem_wstrb. Misalignment checking belongs
to the requester/core before issuing a transaction.

Physical address map
--------------------

The fixed-device base addresses follow the common QEMU RISC-V virt layout.
GPIO and the general-purpose timer are OpenRV64-specific slots. The requested
64 KiB boot ROM starts at QEMU's MROM base but is larger than QEMU's current
0xF000-byte MROM aperture.

    Target       Base                Size
    ------------ ------------------- -------------------
    Boot ROM     0x0000000000001000  0x0000000000010000
    CLINT        0x0000000002000000  0x0000000000010000
    PLIC         0x000000000c000000  0x0000000004000000
    UART         0x0000000010000000  0x0000000000000100
    GPIO         0x0000000010010000  0x0000000000001000
    Timer        0x0000000010020000  0x0000000000001000
    Memory       0x0000000080000000  0x0000000000010000

The SoC reset vector is 0x0000000000001000, the first byte of boot ROM. The ROM
constructs 0x0000000080000000 in x1 and jumps to it, matching the usual QEMU
virt ROM-to-RAM boot shape without implementing firmware services yet.

Decoder behavior
----------------

For a mapped request, the decoder asserts exactly one target valid signal,
subtracts that target's base from mem_addr, forwards the request payload, and
returns only the selected target's ready and read-data response. Unselected
ready or read-data inputs have no effect.

Backpressure from the selected target propagates unchanged. While that target
keeps ready low, the requester keeps the request stable and no other target is
selected.

For an address outside every declared window, no target valid signal asserts.
The decoder completes the request immediately with mem_ready=1,
mem_error=1, and mem_rdata=0. An unmapped write therefore changes no target
state and cannot hang the requester.

An address inside a target window is a successful decode even if the local
offset is reserved by that target. Current peripherals acknowledge reserved
offsets, return zero on reads, and ignore writes. That is target behavior, not
a decode failure.

Downstream target interface
---------------------------

Each target receives the same fields with target-local naming:

    <target>_valid
    <target>_ready
    <target>_write
    <target>_addr[63:0]
    <target>_wdata[63:0]
    <target>_wstrb[7:0]
    <target>_rdata[63:0]

Targets do not currently return their own error signal. The present mem_error
response reports decoder misses only. If a future target can fail a mapped
transaction, its error response must be added to the selected response mux.

Memory target
-------------

openrv64_soc_memory implements 64 KiB by default as 8192 64-bit words. It is
initialized to zero. Reads are combinational, writes commit on the rising edge,
and byte strobes update individual lanes. It acknowledges a valid local
request immediately. The decoder guarantees that routed addresses are within
the 64 KiB memory window.

Boot ROM target
---------------

openrv64_soc_rom implements 64 KiB initialized to zero except for these first
three RV64 instructions:

    addi x1, x0, 1       encoding 0x00100093
    slli x1, x1, 31      encoding 0x01f09093
    jalr x0, 0(x1)       encoding 0x00008067

The first two instructions share the first 64-bit ROM word and the third is in
the low half of the second word. Reads are combinational. Writes are
acknowledged but ignored.

Core error handling
-------------------

Connect decoder mem_error_o to the core mem_error input. A failed instruction
fetch becomes an instruction access fault. A failed data read becomes a load
access fault, and a failed data write becomes a store access fault. The faulting
physical address is reported through the existing trap-value path.
